# 12 - Agent Engineering

## What You Will Learn

Agent Engineering is the practice of designing the system *around* the model rather than the model itself: what scaffolding it runs inside (harness), how you decide when work should self-iterate versus stay a single step (loop), how you decide when a single iterating step should split into a coordinated structure of specialized parts (graph) - and, beyond those three, how you curate what the model sees (context), how you make "good" measurable at scale (evaluation & verifiers), how you build the worlds agents train and are tested in (environment), how you package reusable know-how (memory & skills), and what changes about software delivery once all of that is in place (spec & vibe engineering). Where Prompt Engineering optimizes a single call and Agentic AI covers the mechanics of a single agent loop, this module covers the architectural decisions that sit above both.

## Why It Comes After Agents and Agentic AI

You need to understand what an agent is (Topic 05) and how the base agent loop actually executes - the LLM/Tool Executor/Loop Controller, ReAct, termination conditions (Topic 06) - before the design-level questions here make sense. Harness Engineering asks what surrounds that loop to make it durable. Loop Engineering asks when building a loop at all is worth the setup cost. Graph Engineering asks when a single loop should become a coordinated structure instead. The five notes that follow build on all three: each one names a discipline that became necessary once teams tried to run harnesses, loops, and graphs reliably at scale.
