▶ 1 · Deployment incremental FTP · fresh switch · smoke test

Target: sunmintz.com/learngenai/ (static export, no Node server at runtime) Method: next build (static export) -> incremental FTP sync of out/ via GitHub Actions (fresh wipe + full upload on demand) -> Hostinger shared hosting, then a smoke test

Why static export works

  • next.config.ts: output: "export" -> pure static HTML/CSS/JS, no server needed
  • trailingSlash: true -> every route emits as route/index.html (Apache-friendly)
  • images: { unoptimized: true } -> no Node image-optimization server required

Current workflow (.github/workflows/deploy.yml)

Triggers: push to main (except pushes that only touch vibes/**, **/*.md or .claude/**) and manual workflow_dispatch. One deploy at a time (concurrency: deploy-hostinger, newer pushes queue), 45-minute timeout.

Steps (all actions on their Node 24 releases): actions/checkout@v7 -> actions/setup-node@v7 (Node 22, npm cache) -> npm ci --no-audit --no-fund -> npm run check:content (fails fast before anything uploads) -> actions/cache@v6 restore of .next/cache (keyed on package-lock.json + src/app|components|lib|types + next.config.ts) -> npm run build -> deploy-mode summary -> SamKirkland/FTP-Deploy-Action@v4.4.0 (FTP timeout 120 s) to /domains/sunmintz.com/public_html/learngenai/, incremental (no dangerous-clean-slate; the action keeps .ftp-deploy-sync-state.json on the server and uploads only changed files, deleting removed ones). Excludes **/.DS_Store, **/index.txt, **/__next.*.txt (Next's ~2,500 client-navigation payload files, ~130 MB; links fall back to full page loads). robots.txt is deployed. Last step: a Smoke test (curl, must be 200).

Fresh deploy (wipe + full upload): run the workflow by hand (Actions -> Deploy to Hostinger -> Run workflow) with fresh ticked, or include [fresh deploy] in the pushed commit message. For a PR merge, put it in the PR title (GitHub copies the title into the merge commit message). A Smoke test step then fails the run unless /, the bigram primer, /labs/bigram/index.html and /robots.txt return 200.

Why it is fast now (2026-10-19): next.config.ts sets generateBuildId to a hash of the app code (src/ minus src/content/, package-lock.json, next.config.ts). Next stamps the build ID into every page, so the old random ID changed 261 of 394 output files on every build and, with clean-slate on, the whole site was deleted and re-uploaded over FTP (~30 min). Now an identical rebuild changes 0 files and a one-line content edit changes 2 (that page + search-index.json). A code or dependency change still re-uploads every page, since chunk names change.
