▶ 1 · Deployment Hostinger · manual FTP

Static export (output: "export") built via next build, uploaded to Hostinger by a manually-triggered GitHub Actions workflow. No Node server at runtime; served at sunmintz.com/learngenai/.

Why static export works

  • output: "export" → pure static HTML/CSS/JS
  • trailingSlash: true → every route emits route/index.html
  • images: { unoptimized: true } → no image-optimization server needed

Current workflow — .github/workflows/deploy.yml

name: Deploy to Hostinger
on:
  workflow_dispatch:        # manual trigger only
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - actions/checkout@v4
      - actions/setup-node@v4 (node 20, npm cache)
      - run: npm ci
      - run: npm run build
      - uses: SamKirkland/FTP-Deploy-Action@v4.3.5
        with:
          server: ${{ secrets.FTP_SERVER }}
          username: ${{ secrets.FTP_USERNAME }}
          password: ${{ secrets.FTP_PASSWORD }}
          port: 21
          local-dir: ./out/
          server-dir: /domains/sunmintz.com/public_html/learngenai/

Required secrets

SecretPurpose
FTP_SERVERFTP hostname from Hostinger hPanel
FTP_USERNAMEFTP account username
FTP_PASSWORDFTP account password
Note: server-dir is hardcoded in the YAML, not read from a secret — a previous tracker doc claimed FTP_HOST / FTP_SERVER_DIR secrets existed. That was wrong; corrected here.

Deploy history

  • Workflow was deleted/recreated and switched from auto-trigger to manual-only during June CI fixes (untracked package-lock.json/tsconfig.json had been blocking npm cache and path-alias resolution)
  • Latest change (2026-06-29, e5f3191) removed an unused environment choice input, back to a bare workflow_dispatch
  • No CI runs on push/PR — lint/typecheck/build are not verified automatically before merge
